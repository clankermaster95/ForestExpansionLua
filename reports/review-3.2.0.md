## r2 follow-up: why the earlier review missed the reported failures

The checks established source/archive properties and selected behavior under mocked natives. They did not prove that the user had loaded that artifact, or that solo commands interacted correctly with the original result triggers. Windows Restart Manager identified Warcraft holding installed build `805374729374`, which predates debug commands; the editor copy and its temporary test map matched older `86e1a4f...` as well. The latest installed build at diagnosis was `8c05af7...`. Keeping the same visible map name obscured this distinction, and a Windows sharing lock prevented deletion of the old installed copy. Reporting latest-only cleanup as complete before the file disappeared was incorrect.

Independent source defects were also found: solo testing left automatic match-result triggers active, and `Remove_Selector` used a tautological condition that allowed any unit buyer to be killed. r2 adds solo-only conditions to all 14 result triggers, secondary result-helper guards, and a selector-type filter. The real trigger initializers and callbacks are exercised together with the actual bootstrap order in `tests/solo_startup.lua`: skip at 0/5/25 seconds, both solo roles, 400 simulated seconds, delayed result-trigger re-enable, all Ancient deaths, level 20, leaving, and the multiplayer boundary. These tests use a deterministic native double and do not establish native engine behavior. The visible r2 title/banner and instructions now identify which artifact must be retested.
